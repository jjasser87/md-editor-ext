## Runtime findings from QA harness (numbered continuing; each has a failing test in qa/tests, title prefixed [BUG-n])
7. [VERIFIED FIXED at 10:48 ET build index-mr2HYmiP.js: top-bar #btn-source removed, single toolbar toggle, state.source follows editor.isSourceMode()][med] **Two Markdown/Source toggles that desync.** The editor toolbar has its own "Markdown" button (`.mdx-toolbar [data-cmd=source]`, calls `setSourceMode` internally) in addition to the page-level `#btn-source`. main.js only tracks `state.source`/`#btn-source[aria-pressed]` when its own button is used. Repro: open editor -> click toolbar "Markdown" (source mode ON, `state.source` still false, `#btn-source` aria-pressed=null) -> click `#btn-source`: `toggleSource()` flips state.source to true and calls `setSourceMode(true)` which is a no-op -> still in source mode, and `#btn-source` now says pressed. Second click is needed to leave. Reverse also: `state.source=true` while editor is WYSIWYG after using the toolbar button to leave. Tests: 03 [BUG-7], 09 [BUG-7], [BUG-7b]. Fix: remove one button (e.g. drop `#btn-source` or the toolbar one) OR make main.js's toggle read `editor.isSourceMode()` (`state.source = !editor.isSourceMode()`) and have createEditor accept an `onSourceModeChange` callback to sync aria-pressed.
8. [VERIFIED FIXED][low-med] **Task-list items render checkbox above text (broken layout).** editor.css targets `li[data-type="taskItem"]` but @tiptap/extension-list v3 renders `<li data-checked=...>` with NO `data-type` on the li (only `ul[data-type="taskList"]`). So `display:flex` is never applied: checkbox on one line, text on the next (li height 51px vs ~26px; text top is ~20px below checkbox in both themes). Evidence: qa/screens/bug8-task-list-before.png vs qa/screens/bug8-task-list-with-suggested-css.png (also visible in screens/editor-light.png). Tests: 09 [BUG-8], [BUG-8b]. Fix: change selectors to `.ProseMirror ul[data-type="taskList"] > li` (and `> li > label`, `> li > div`, `> li[data-checked="true"] > div`). _(Editor Dev: task-list CSS selectors now target ul[data-type=taskList] > li (+ li has data-type via TaskItem HTMLAttributes); verified light+dark in headless Chromium)_
9. [VERIFIED FIXED][med] **Escapes are dropped on save so literal text becomes real markdown structure on next open.** Serializer unescapes block-start characters: `\# not heading` -> `# not heading` (becomes an H1 when reopened), `\- x` -> `- x` (list), `\+ x`, `1\. not a list` -> `1. not a list` (ordered list), `1\)`, `\---` -> `---` (hr). Verified by comparing ProseMirror doc of original vs. doc re-parsed from getMarkdown(): STRUCTURE CHANGED (fixture 09-escapes.md: paragraph -> orderedList). Also `\> quote` is emitted as `&gt; quote`, `\<div\>` as `&lt;div&gt;` (entity churn), and `Snake_case_word and 2 * 3 * 4.` is emitted as `Snake\_case\_word and 2 \* 3 \* 4.` (harmless but noisy diffs; idempotent though). Also `<https://x>` autolinks become `[https://x](https://x)`. Tests: 04 fixture 09-escapes.md, 04 [BUG-9]. Fix: in extensions.js override the text-node markdown rendering (or post-process in normalizeMarkdownOutput for paragraph-start `^(\s*)(#{1,6}\s|[-+*]\s|\d+[.)]\s|>|---)` by prefixing `\`) and avoid escaping `_`/`*` intra-word/spaced. _(Editor Dev: block-start escapes re-emitted (\#, \-, \+, 1\., 1\), \---, \>), no &gt;/&lt; entities, inert _/* left alone, <autolinks> preserved; doc-structure round-trip asserts in roundtrip.test.mjs)_
10. [VERIFIED FIXED][med] **Silent content loss for HTML/footnote constructs on open+save.** `<!-- comment -->` is deleted; `<details><summary>S</summary>body</details>` -> `S\n\nbody` (tags removed); `H<sub>2</sub>O <kbd>Ctrl</kbd>` -> `H2O Ctrl`; footnote `Foot[^1]` + `[^1]: the note` -> `Foot\[^1\]\n\n\[^1\]: the note` (definition becomes literal text); `<div align=center><img></div>` -> bare `![](a.png)`. A user who just opens and saves a README loses these. Reference-style links/definitions are inlined (`[use][ref]` -> `[use](url "T")`, acceptable but is a diff). Test: 09 [BUG-10].
